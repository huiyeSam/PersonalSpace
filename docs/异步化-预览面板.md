# 异步化：GUI 世界预览面板

> 引入版本：1.0.64-mc1.12.2
> 涉及文件：`gui/WPreviewPanel.java`（重写）

## 要解决的问题

`WPreviewPanel.updatePreview()` 原来在**渲染线程**同步执行，每次配置哈希变化
（拖动滑块、切换方块、改数字）都触发一次：

1. 最多 7 个方块的颜色提取：`ImageIO.read` 读贴图 PNG（**磁盘 IO**），失败时
   `glGetTexImage` 把**整张方块图集**从 GPU 读回来（16MB+ 回读，管线停顿）；
2. 128×128 = 16384 像素的布局计算。

后果是设置界面操作时明显掉帧。

## 实现方案

### 三段式流水线

```
渲染线程 drawImpl()
  ├─ 计算配置哈希（含 textureColorVersion）
  ├─ 有完成结果且哈希匹配 → applyResult()：拷贝像素 + 上传纹理
  └─ 哈希变化且无任务在跑 → submitTask()：快照配置、解析 sprite、提交任务
后台线程 (PersonalSpace-PreviewRenderer, 单线程 daemon)
  └─ resolveColorCpu() 逐方块解析颜色（缓存 → ImageIO → 帧数据）
     computePixels() 计算 16384 像素到独立数组
渲染线程 下一帧 applyResult()
  ├─ 对 CPU 路径失败的贴图做一次 GPU 回读兜底（每 icon 最多一次）
  └─ 像素拷入 DynamicTexture，updateDynamicTexture()
```

### 线程分工原则

| 工作 | 线程 | 原因 |
|---|---|---|
| 读取 config、构建快照 | 渲染线程 | config 被 GUI 在同线程修改，快照避免竞态 |
| 解析 `TextureAtlasSprite`、材质地图色兜底 | 渲染线程 | 模型表读取便宜且需要 `Minecraft.world` |
| ImageIO 读 PNG、帧数据平均色、像素计算 | 后台线程 | 纯 CPU，占大头 |
| `glGetTexImage` 图集回读、`updateDynamicTexture` | 渲染线程 | OpenGL 上下文只在渲染线程 |

后台线程**绝不接触** `DynamicTexture`、config 对象和 OpenGL。

### 关键数据结构

- `PreviewParams`：不可变快照（间隔/马路宽度/预设/中心标记 + 7 个 `ColorSlot`）。
- `ColorSlot`：一个待解析颜色 = sprite（渲染线程解析）+ fallback（地图色）+ color
  （后台填充，0 = 未解析）。
- `PreviewResult`：哈希 + 像素数组 + 参数，通过 `volatile pendingResult` 发布。

### 内存可见性

后台任务结束时**先写 `pendingResult` 再写 `taskInFlight = false`**（两个 volatile）。
按 Java 内存模型，渲染线程看到新 result 就一定能看到 flag 已清除，不会提前提交
重复任务。

### 过期结果丢弃

拖动设置时哈希每帧都变：任务完成时若 `result.hash != 当前哈希` 直接丢弃，
下一帧提交新任务。单线程执行器 + `taskInFlight` 标志保证最多一个任务在跑，
连续拖动不会堆积任务队列。

### 颜色缓存与升级

- `textureColorCache` 改为 `ConcurrentHashMap`（后台线程也会写）。
- `textureColorVersion`（AtomicInteger）：任何新颜色进缓存都 +1，并计入配置哈希。
  效果：某个方块第一次显示用地图色兜底，后台解析出真实贴图颜色后版本号变化，
  预览自动重算一次，颜色"升级"为准确值。
- GPU 回读兜底只在 CPU 路径（PNG + 帧数据）都失败时执行；失败的 icon 记入
  `glFallbackFailed` 不再重试，避免每帧回读图集。
- 后台任务异常时发布一张纯灰图作为结果：哈希被消费，不会无限重试刷屏报错。

## 已知行为说明

- 颜色升级会让预览在极个别方块上先显示近似色、约一帧后变成准确色，属预期。
- 旧代码中 `computeGapColor` 是从未被调用的死代码（预览本来就不渲染马路/间隔的
  颜色，只渲染边界和中心标记），重写时删除了这些死参数，**视觉行为与旧版一致**。
  如需让预览显示马路，是另一个功能改动，不属于本次异步化。
